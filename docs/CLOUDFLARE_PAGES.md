# Cloudflare Pages preview hosting

> AskRef implementation update: see [ASKREF.md](ASKREF.md) for the Qwen3 Worker, supported rate limiter, service-binding setup, draft queue and scenario review workflow. The older Pages-only account status below is historical; these local changes have not deployed the Worker or enabled live inference.

`wrangler.toml` configures this repository for Cloudflare Pages with Vite's `dist/` output and Functions at `/api/askref` and `/api/me`. The project `playersmart-preview` is deployed at https://playersmart-preview.pages.dev/. Its Neon Auth verification URLs are set as Cloudflare secrets. The AskRef AI Gateway and supported rate limiter are not yet provisioned, so AskRef deliberately fails closed.

## Connect through the Cloudflare dashboard

1. Push this repository to an approved GitHub repository. Keep real youth information and `.env.local` out of Git.
2. To deploy manually, authenticate Wrangler to the intended account and run `npm run deploy:pages`. A GitHub-connected Pages build can be configured separately.
3. Select **Vite** (or configure the equivalent static build), set the build command to `npm ci && npm run build`, and set the output directory to `dist`.
4. Configure the Workers AI binding (`AI`) and create the `playersmart-askref` AI Gateway in the same Cloudflare account. Confirm its billing, caching, logging, and rate-limit settings before enabling it.
5. Configure `NEON_AUTH_JWKS_URL` and `NEON_AUTH_BASE_URL` as server-side Pages Function variables so AskRef can verify signed-in requests. Do not add secrets or private values as `VITE_*` variables.
6. Deploy a preview first. Verify the sign-in/demo wording, theme, navigation, client-side routes, and AskRef citations. Workers AI usage may incur Cloudflare charges.
7. Only enable a production custom domain after the organization approves the public-demo scope and privacy wording.

For local Cloudflare Pages Function development, install dependencies, authenticate Wrangler with the intended Cloudflare account, add `NEON_AUTH_JWKS_URL` and `NEON_AUTH_BASE_URL` to ignored `.dev.vars`, and run `npm run dev:pages`. In separate terminals run `npm run dev -- --port 5187` and `npm run dev:api`; Vite proxies `/api/askref` to Pages Functions on port 5188 and the other local APIs to port 4180. This invokes the real Cloudflare Workers AI binding and may incur usage charges. The Vite-only `npm run dev` mode does not execute Pages Functions.

The Pages Function accepts only signed-in AskRef requests and enforces a per-authenticated-user Cloudflare rate limit (10 requests/minute). It retrieves versioned PDSA excerpts, then relevant IFAB 2025/26 pages server-side, and calls Cloudflare AI Gateway / Workers AI using `@cf/qwen/qwen3-30b-a3b-fp8`. PDSA modifications take precedence. Restart placement is selected from a fixed server-side allowlist; diagrams are static SVGs and never generated by the model. It skips model-response caching. Disable prompt/response logging at the Gateway before enabling AskRef. The client submits only the rules question; youth/player records are not included in the model request. Do not enter personal information in questions. This does **not** create a player-data API or organization/team authorization. The production AskRef path is the Pages Function.

Cloudflare Pages' Wrangler configuration does not accept the Workers Rate Limiting binding. AskRef therefore fails closed with 503 until a supported account-level rate limit is configured or the API is moved behind a Worker that supports the rate-limit binding. Do not deploy an unthrottled AI endpoint.

The account has a Pages project and deployment, but no custom domain or GitHub build connection. The Workers AI binding and Auth verification secrets are configured. The AI Gateway and supported rate limiter are outstanding; until configured the AskRef handler returns 503 by design.
