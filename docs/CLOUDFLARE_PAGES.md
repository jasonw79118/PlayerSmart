# Cloudflare Pages preview hosting

`wrangler.toml` configures this repository for Cloudflare Pages with Vite's `dist/` output and a Pages Function at `/api/askref`. The Function uses a Workers AI binding routed through the `playersmart-askref` AI Gateway. It does not deploy anything by itself and contains no credentials.

## Connect through the Cloudflare dashboard

1. Push this repository to an approved GitHub repository. Keep real youth information and `.env.local` out of Git.
2. In Cloudflare, create a Pages project connected to that repository.
3. Select **Vite** (or configure the equivalent static build), set the build command to `npm ci && npm run build`, and set the output directory to `dist`.
4. Configure the Workers AI binding (`AI`) and create the `playersmart-askref` AI Gateway in the same Cloudflare account. Confirm its billing, caching, logging, and rate-limit settings before enabling it.
5. Configure `NEON_AUTH_JWKS_URL` and `NEON_AUTH_BASE_URL` as server-side Pages Function variables so AskRef can verify signed-in requests. Do not add secrets or private values as `VITE_*` variables.
6. Deploy a preview first. Verify the sign-in/demo wording, theme, navigation, client-side routes, and AskRef citations. Workers AI usage may incur Cloudflare charges.
7. Only enable a production custom domain after the organization approves the public-demo scope and privacy wording.

For local Cloudflare Pages Function development, install dependencies, authenticate Wrangler with the intended Cloudflare account, add `NEON_AUTH_JWKS_URL` and `NEON_AUTH_BASE_URL` to ignored `.dev.vars`, and run `npm run dev:pages`. In separate terminals run `npm run dev -- --port 5187` and `npm run dev:api`; Vite proxies `/api/askref` to Pages Functions on port 5188 and the other local APIs to port 4180. This invokes the real Cloudflare Workers AI binding and may incur usage charges. The Vite-only `npm run dev` mode does not execute Pages Functions.

The Pages Function accepts only signed-in AskRef requests and enforces a per-authenticated-user Cloudflare rate limit (10 requests/minute). It retrieves versioned PDSA excerpts, then relevant IFAB 2025/26 pages server-side, and calls Cloudflare AI Gateway / Workers AI using `@cf/meta/llama-3.2-3b-instruct`. PDSA modifications take precedence. Restart placement is selected from a fixed server-side allowlist; diagrams are static SVGs and never generated by the model. It skips model-response caching. Disable prompt/response logging at the Gateway before enabling AskRef. The client submits only the rules question; youth/player records are not included in the model request. Do not enter personal information in questions. This does **not** create a player-data API or organization/team authorization. The production AskRef path is the Pages Function.

The Pages rate-limit namespace ID in `wrangler.toml` is a placeholder: provision a unique namespace ID for the Cloudflare account before deployment. A missing limiter intentionally disables the endpoint (503) rather than allowing unthrottled inference.

No Cloudflare account, AI Gateway, domain, GitHub connection, deployment token, or Pages deployment has been configured from this repository. The function is code-ready but will return a configuration error until those account-side bindings/variables are set.
